# kits/mw — the two memory-one runs (main text Figure 4a–c, SI Figure 4a–c)

The Wright–Fisher process over the 16 binary memory-one strategies, at the parameters of the two memory-two runs: `sf1.f` N = 1000, β = 100, μ = 10⁻², 10⁷ generations (main text Figures 4a–c and 5a–c, SI Figures 2i–p, 6c, 7c); `sf2.f` N = 100, β = 3, μ = 10⁻⁴, 10⁸ generations (SI Figures 2a–h, 4a–c, 5a–c, 6b, 7b). `sf1s.f` and `sf2s.f` are convergence controls with the run length cut 100-fold and independent seed bases; they are not used in the paper. This kit reads its own 512-row `games.dat` (`../../games/games_m1.dat`, the same 512 games as rows 456–967 of the memory-two list), so its task index is isl = 3·ipt + 3.

## Source

The four sources are generated by `mksf.py` from `../dw1/sf.f` (sha256 asserted) by 26 named substitutions: the strategy space is cut to the 16 memory-one strategies, each embedded as the memory-two strategy that ignores the round before (index k ↦ 15·Σ_j b_j(k)·16^j, so ALLC = 65535, TFT = 3855, WSLS = 61455), the hash cache becomes a 16 × 16 table filled once per game by dw1's own `payf3` and dw1's own payoff lines, initial genomes (four fair coins per individual instead of sixteen) and mutants are drawn over the 16, and the output is resized; the rest of the generation loop, which draws its random numbers in the order and amounts of dw1's, and the task decode are dw1's. `sf1.f` and `sf2.f` differ in the five run-parameter lines (and two header lines). A memory-one strategy's bit k is its answer after the outcome k = CC, CD, DC, DD (own move first): ALLD = 0, Grim = 1, TFT = 5, WSLS = 9, ALLC = 15. `python3 mksf.py` regenerates the four sources byte for byte.

## Files

| file | what |
|---|---|
| `compile.sh` | builds `sf1.x sf2.x sf1s.x sf2s.x` (or the named ones) |
| `mksf.py` | builds the four sources from `../dw1/sf.f` (its input paths made relative for the repository) |
| `pack.py` | packs `run1/` (`run2/`, ...) into `mw1_e4.tsv` and `mw1_e4.rep.tsv` (all 512 cells required; `--dev` for a short local build) |

| `prod2.slurm` | **production array of the paper**, sf2, `--array=3-1536:3` |
| `prod2s.slurm` | the control array of sf2s |
| `sf1.f` | N = 1000 run (memory one, large population) |
| `sf1s.f` | convergence control of sf1 (10⁵ generations, seed base 12000000; not in the paper) |

Not stored here, because every kit shares them: `payf2.f`, `payf3.f` (the stationary distribution of the 16-state pair
chain and the pair payoffs), `mt.f`, `mtb.f` (the Mersenne twister) and `games.dat`. `bash ../stage.sh mw` copies them
from `../../src/` and `../../games/` into this directory, which is then exactly the directory that ran on the cluster.

## How it was run

On the cluster, in this directory:

    bash ../stage.sh mw
    bash compile.sh                      # -> sf1.x sf2.x sf1s.x sf2s.x
    bash submit.sh probe1 ; bash verify.sh probe1     # likewise probe2
    bash submit.sh prod1  ; bash verify.sh prod1      # likewise prod2 (and the controls prod1s, prod2s)
    python3 pack.py run1 packed          # -> packed/mw1_e4.tsv, packed/mw1_e4.rep.tsv (run2 -> mw2_e4.*)

Author's cluster settings (Harvard FASRC Cannon), kept as they ran: the Slurm partition (`#SBATCH -p shared`), the compiler module (`module load intel/25.2.1-fasrc01`, `ifx -O3 -xHost -fp-model precise`) and the cross-project job ledger `~/jobs.tsv` that `submit.sh` appends to (`../README.md` shows how to make that append conditional on `PRFR_LEDGER`). Change these for another cluster; nothing else in the kit depends on them. The format of every output file and pack is described in `../../README.md`.
