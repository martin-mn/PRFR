# kits/f1 — bit-for-bit regeneration of dw1 with per-replicate output (SI Figure 11)

The run of `../dw1` regenerated with its own parameters and seeds and with the per-replicate count file added, so that the per-replicate atom shares of SI Figure 11 exist for the principal maps themselves. Every summary, w- and h-file of the 512 games is byte-identical to dw1's (all 1536 files compared with `cmp`).

| run | N | β | μ | ε | ν | generations | replicates | tasks (isl) | seed base s0 | display items |
|---|---:|---:|---:|---:|---:|---:|---:|---|---:|---|
| `f1` | 1000 | 100 | 10^-2 | 10^-4 | 1 | 10^7 | 10 | 1368–2901:3 | 8000000 | SI Fig 11d-f (per-replicate atom shares) |

Seeds: replicate r (1..10) of task isl ran on the Mersenne-twister seed s0 + 10 (isl − 1) + r (`iseed=iseedb+(isl-1)*nper+irep` in the source); every seed is listed in `../../seeds_by_game.csv`.

## Source

`sf.f` is generated by `../mkkits.py` from `../dw3/sf.f` by asserted substitutions (`diff ../dw3/sf.f sf.f` is the audit): the header comment, `n`, `iseedb`, `uval`, `bval`, and one functional addition shared by all kits of 2026-09-22: after every replicate its 65536 counts are written to the stream file `r<task>` (unit 8, 524288 bytes per replicate), from which `pack.py` computes the per-replicate atom shares (`.rep`) with `atoms512.bin`. The addition does not touch the generation loop or the random stream: `python3 ../mkkits.py test` builds dw3's parameters with and without it and finds the summary, w- and h-files byte-identical (re-run for the repository on 2026-09-24: IDENTICAL). Regenerating the kits from dw3 with `python3 ../mkkits.py` reproduces `sf.f`, the scripts and `pack.py` byte for byte (its README.md is the author's; this one replaces it). The seed base is the original run's (8000000).

## Files

| file | what |
|---|---|
| `compile.sh` | `bash compile.sh 1e7` builds `sf_1e7.x` (the run length is patched into `data itv`) |
| `pack.py` | packs `run_1e7/` into `<kit>_<e>.{idx,bin,win,rep}`; the `.rep` needs `../atoms512.bin` (made by `../stage.sh`) |
| `probe_e4.slurm` | 8-cell probe of the e4 stride |
| `prod_e4.slurm` | **production array of the paper** (e4 stride), 512 tasks |
| `sf.f` | the main program exactly as it ran (the Wright–Fisher generation loop, the payoff cache, the output) |
| `submit.sh` | stages `games.dat` into the run directory, submits one array with `sbatch --parsable`, records its id |
| `verify.sh` | completion per task from `sacct`, and per cell from the output files |

Not stored here, because every kit shares them: `payf2.f`, `payf3.f` (the stationary distribution of the 16-state pair
chain and the pair payoffs), `mt.f`, `mtb.f` (the Mersenne twister) and `games.dat`. `bash ../stage.sh f1` copies them
from `../../src/` and `../../games/` into this directory, which is then exactly the directory that ran on the cluster.

## How it was run

On the cluster, in this directory:

    bash ../stage.sh f1
    bash compile.sh 1e7
    bash submit.sh probe_e4 ; bash verify.sh probe_e4
    bash submit.sh prod_e4  ; bash verify.sh prod_e4
    python3 pack.py run_1e7 packed        # -> packed/f1_e4.{idx,bin,win,rep}

Author's cluster settings (Harvard FASRC Cannon), kept as they ran: the Slurm partition (`#SBATCH -p shared`), the compiler module (`module load intel/25.2.1-fasrc01`, `ifx -O3 -xHost -fp-model precise`) and the cross-project job ledger `~/jobs.tsv` that `submit.sh` appends to (`../README.md` shows how to make that append conditional on `PRFR_LEDGER`). Change these for another cluster; nothing else in the kit depends on them. The format of every output file and pack is described in `../../README.md`.
